# 将来API仕様

**設計のみ。Phase 1には以下の稼働エンドポイントもクライアントもありません。** URLは実装前の論理パスであり、接続可能なサービスを示すものではありません。

## 共通要件

HTTPSのみを利用し、接続先を固定します。入力の型・長さ・許可値・JSON深度・本文上限を確認し、JSON以外や未知フィールドを拒否します。APIキーやライセンスキーはURLへ入れません。レスポンスでは秘密値と内部例外を返さず、固定エラーコードとリクエスト識別子を用います。

| ステータス | 用途 |
| --- | --- |
| 400 | 不正な形式・許可外入力 |
| 401 / 403 | 認証失敗・権限不足 |
| 409 | 上限、重複、状態競合 |
| 429 | レート制限。Retry-Afterを返す |
| 503 | 外部依存の一時障害。再試行可能 |

ブラウザー利用のマイページは安全なHttpOnly・Secure・SameSite CookieとCSRF対策を使います。サーバー間APIにCORSの許可だけで認証を代替しません。

## 販売と購入者

| メソッド・パス | 認証 | 処理 |
| --- | --- | --- |
| POST `/v1/checkout` | 購入者セッション・CSRF | 許可されたmonthly/yearlyをPriceへ対応付け、テストCheckout作成 |
| POST `/v1/portal` | 購入者セッション・CSRF | 本人のCustomer Portalを作成 |
| GET `/v1/account` | 購入者セッション | 本人の契約・期限・認証サイト一覧 |
| POST `/v1/stripe/webhook` | Stripe署名 | 重複防止・現在状態照合・契約同期 |

Webhookは署名検証前にJSONの再エンコードを行いません。イベントはストレージへ記録後にトランザクションで処理し、再送で二重発行しません。Checkout成功のブラウザー画面は未確定状態も表示できるようにします。

## ライセンス

| メソッド・パス | 認証 | 処理 |
| --- | --- | --- |
| POST `/v1/licenses/activate` | ライセンスキー・初回サイト所有確認 | 有効契約と10サイト制限を検証し、サイト資格情報を発行 |
| POST `/v1/licenses/status` | サイト資格情報・要求署名 | 本サイトの契約状態・期限のみ返却 |
| POST `/v1/licenses/deactivate` | サイト資格情報・要求署名 | 本サイトだけ認証解除 |
| POST `/v1/account/activations/revoke` | 購入者セッション・CSRF | 所有ライセンスのサイト認証を解除 |

初回認証には強いレート制限を適用します。任意URLへの所有確認リクエストはSSRFを招くため、サイトからの署名チャレンジや管理者確認を使い、採用する所有確認方法を別途監査します。

サイトAPIは `activation_id`、時刻、暗号学的nonce、本文のSHA-256を含む正規化要求へHMAC-SHA256を付けます。HTTPメソッド・固定パス・タイムスタンプ・nonce・本文ハッシュの並びを固定し、比較は定数時間で行います。許容時刻幅とnonceの一意制約で再送攻撃を拒否します。nonceストア障害時に認証変更処理を続行しません。サイト資格情報は暗号化保管し、ログへ出しません。ネットワーク再試行には別のidempotency keyを使い、正当な再試行とリプレイを区別します。

## 防御ルールと脆弱性情報

ルール配信には発行元、スキーマ版、ルール版、発行・失効日時、対象コンポーネント・バージョン範囲、SHA-256、署名鍵IDを含めます。情報源のURL、取得日時、情報源の更新日時、利用条件、照合方式を保存します。無料の公開情報を収集できることと再配布が許可されることを区別し、フィードの契約・ライセンスを確認します。

検証済み公開鍵で署名・対象・期限・ダウングレードを確認し、サイズ制限付きで取り込みます。配信元障害は最後の検証済みルールを維持し、鮮度が古い旨を管理者へ示します。攻撃パターンは固定ルール形式とし、遠隔PHPコードの実行や任意正規表現の無制限実行を許しません。

## 自動更新

| メソッド・パス | 認証 | 処理 |
| --- | --- | --- |
| POST `/v1/updates/check` | 有効サイト資格情報 | チャネル・互換性に合う署名済みmanifestを返す |
| POST `/v1/updates/download-ticket` | 有効サイト資格情報 | 短時間有効・対象ZIP固定のダウンロード権を発行 |

manifestには製品ID、版、dev/rc/stable、必要PHP/WP、ZIPサイズ、SHA-256、更新履歴、発行日時、署名鍵IDを含めます。ZIPのハッシュだけで配布元の真正性は保証できないため、manifest自体へ公開鍵署名を付けます。署名用秘密鍵は販売Webプロセスから分離し、公開鍵ローテーションを事前に設計します。

プラグインは署名、製品ID、チャネル、版、上限サイズを検証してからZIPを取得し、ハッシュ・構造・パストラバーサル・予期しない実行ファイルを検証します。失敗時は既存版を維持します。失効・漏洩した鍵の扱い、障害時ロールバック、並行更新はリリース前に実機検証します。開発版・RCがStableチャネルへ混入しないことを試験します。

## Cloudflare

対象ゾーンと必要な機能から最小権限を決定します。トークンはサーバー側のシークレットとして管理し、表示画面・ログ・ZIPへ返しません。API応答のエラーコード、プラン機能、対象ゾーン権限を実際に診断し、「無料プランでは一切使えない／すべて使える」と固定しません。

一時ルールにはFSU所有識別子と有効期限を付け、他者のルールを解除しません。429はRetry-Afterに従い、バックオフ・ジッター・キュー上限を用います。API障害時はWordPressローカル防御を維持し、無限再試行や無制限ルール作成を防ぎます。期限到来の解除失敗は管理者へ通知し、再照合ジョブで復旧します。
