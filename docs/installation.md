# インストール・設定・復旧

## 検証環境

開発版ZIPを、バックアップを取得した隔離WordPressへインストールします。対象候補はWordPress 7.0.8 / 7.1.4、PHP 8.2〜8.5です。実際に検証済みの組み合わせは `verification.md` を参照してください。ZipArchiveがない環境ではZIP取得を使用できません。

Phase 1は単一サイト用です。ネットワーク有効化やマルチサイトでのログ・権限分離は対象外とし、有効化を拒否します。

## ログ保存先

Webサーバーの公開ディレクトリ外へ、WordPressを実行するOSユーザー専用のフォルダーを用意します。次を `wp-config.php` のWordPress読込より前へ追加します。

```php
define( 'FSU_PRIVATE_DIR', '/srv/private/fortress-security-ultimate' );
```

このパスは例です。自分のホスティングで許可された公開領域外のパスに変更します。WordPress設置先、DocumentRoot、その内部のパス、シンボリックリンクを利用しないでください。保存先の0700とファイル0600を利用し、読み書きできるOSユーザーを限定します。

省略時はサイト別のシステム一時領域を使用します。一時領域の清掃やOS再起動による削除は168時間保持より優先されます。ログを保存する必要がある場合は、常設の専用パスを指定してください。ログはデータベースへフォールバックしません。

## 定期整理

プラグイン有効化時に毎時の `fsu_prune_logs` を登録します。WordPress標準のWP-Cronはアクセスに依存するため、アクセスがない間は期限超過ログの削除が遅れる場合があります。システムCronから定期的にWP-CLIを実行すると、サイトへの外部アクセスなしで整理できます。

```sh
wp cron event run fsu_prune_logs --path=/absolute/path/to/wordpress
```

実際のWordPressパスと実行OSユーザーを環境に合わせ、システムCronへ登録してください。セーフモード中は定期整理を停止するため、復旧後に再実行します。

## 動作確認

1. 開発版ZIPをプラグイン画面からアップロードし、有効化する。
2. 管理メニューを開き、開発版表示と未実装機能の表示を確認する。
3. 環境診断を実行し、警告の意味を読む。診断結果だけで安全性が保証されるわけではない。
4. 設定を保存し、再表示後にも値が維持されることを確認する。
5. 1 / 24 / 168時間のZIPを取得し、JSONL、環境情報、README、manifestを確認する。
6. 一般ユーザーが管理操作やZIP取得を行えないことを隔離環境で確認する。
7. 設定復元とセーフモードによる復旧を試す。

## 管理画面以外からの復旧

管理画面へ入れないときは、ホスティングのファイルマネージャー、SFTP、SSHなど管理者自身の経路を使い、WordPress読込前に次を設定します。

```php
define( 'FSU_SAFE_MODE', true );
```

Phase 1では攻撃遮断エンジンがまだ存在しません。セーフモードは将来の防御処理も含めた緊急停止のための基盤であり、侵害の復旧を自動完了する機能ではありません。

読込自体で問題が続く場合は、`wp-content/plugins/fortress-security-ultimate` を一時的に別名へ変更して無効化します。原因を調査してからディレクトリ名を戻し、必要に応じて再有効化します。設定を一度に削除する前にバックアップを取得してください。

## 削除時

開発中のログはプラグインディレクトリ外へ保存されます。プラグインを削除するだけで外部の専用ログディレクトリが消えるとは限りません。保持方針を確認し、必要なZIPを取得した後に管理者が保存先を整理します。任意のパスをアンインストール時に再帰削除する設計にはしません。
