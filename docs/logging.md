# 構造化ログ

## 保存方針

ログはUTCの時間単位でJSONLへ保存します。JSONLは1行につき1つのJSONオブジェクトを持つ形式です。イベント発生時に同期記録し、同時処理ではロックを利用します。保持対象期間は168時間、初期容量上限は524,288,000 bytes（500 MiB）です。上限を超えないよう古いログを整理し、1件あたりの長さも制限します。ファイル分割の時間、保持判定、ZIP抽出の時間範囲はUTCで扱います。

期限切れの時間ファイルの削除は、次の書き込みまたは毎時の `fsu_prune_logs` Cronイベント実行時に行います。168時間の境界を跨ぐファイルの行単位整理は毎時Cronで行い、通常の書き込み時には全行を再解析しません。アクセスのないサイトでWP-Cronが動かない間や、セーフモードで定期整理を停止している間は、168時間を過ぎたデータがディスクへ残る場合があります。時刻どおりの削除が必要な環境では、システムCronからWordPressのCronを定期実行してください。外部からサイトへアクセスを送る必要はありません。

各時間ファイルにも8 MiBの上限があります。到達後は次の時間ファイルへ切り替わるまで追加レコードを保存しません。ロックが使用中の場合やディスク障害でもレコードを保存できない場合があります。ログは完全な要求履歴や全イベントの損失なき記録ではありません。

ログレベルは `error` / `info` / `debug` / `trace`。カテゴリーは system、php、wordpress、internal、waf、integrity、cloudflare、license、update、performance、admin、audit を使います。カテゴリーが用意されていても、その機能が実装済みという意味ではありません。StableではDebug・Traceを標準無効とし、必要なセキュリティイベントは保持する方針です。

## 機密情報の排除

固定イベントコードと許可された数値・真偽値・検証済みバージョン情報のみを受け付けます。自由記述文字列を後から正規表現で伏せる方式だけには依存しません。許可されていないキーと値は除外します。

Cookie、パスワード、APIトークン、ライセンスキー、HTTPヘッダー、リクエスト本文、IPアドレス、メールアドレス、URL、絶対パス、ユーザーID、例外メッセージ全文は保存しません。PHPエラーは種別と行番号などの限定メタデータだけを記録します。既存の別プラグイン等によるPHPエラーハンドラーがある場合はそのハンドラーを変更せず維持するため、FSUによる通常PHP警告の収集は行いません。終了時の致命的エラーメタデータとWordPressの `WP_Error` イベントは引き続き収集対象です。障害解析に不足する情報がある場合も、秘密を含むリクエスト丸ごとの記録は追加しません。

既存ログファイルも信頼せず、ZIP作成時にJSONとして解析し直し、同じ許可リストを再適用します。破損行や許可外データをそのままZIPへコピーしません。

## ZIPエクスポート

管理者は直近1時間・24時間・168時間から選択します。nonceと権限はダウンロード要求ごとに検証します。境界では行ごとの時刻で対象を判定し、単に時間単位ファイル全体をコピーしません。

ZIPにはログ、機密情報を含まない環境概要、プラグイン版、Gitコミット識別子、README、解析用 `manifest.json` を含めます。開発環境のソース未コミット状態やパッケージビルド情報は検証記録も参照してください。サイトURL、サーバーの絶対パス、認証情報を環境情報へ含めません。

ZIPは解析後のJSONL内容を最大16 MiBに制限します。容量設定に応じてさらに小さくなり、上限で打ち切られた場合はmanifestの `truncated: true` に記録します。指定した7日間のすべてが常にZIPへ含まれるとは限りません。ZIP生成前に期限切れファイルを整理してから空き容量を確認します。出力のために保持中の入力ログを消す必要がある場合は、出力を中止します。通常のログ書き込みによる容量整理とは区別します。

ZIPは非公開ディレクトリで作成し、レスポンス後に一時ファイルを削除します。OS・PHP処理の強制終了では削除が完了しない可能性があるため、保存先の整理処理と容量監視も必要です。生成したZIPは15分間、ダウンロード中の容量整理による削除から保護します。この保護はダウンロードの完了保証や正確な15分後の削除を意味せず、強制終了で残ったZIPは次の整理時に削除します。ログ取得を外部から直接参照する公開URLは提供しません。

## ChatGPT Workでの解析

ZIPのmanifest、README、環境概要を読み、対象期間とビルド識別子を確認してからJSONLを解析します。イベント件数や時間帯の傾向を確認できますが、Phase 1ではWAF攻撃件数は発生しません。ログがないことを「攻撃がない」と解釈しないでください。情報を意図的に最小化しているため、要求内容を完全再現することはできません。

## 性能イベント

詳細ログが有効、performanceカテゴリーが有効、セーフモードが無効の場合のみ、要求終了時に `Debug` の `performance.request` を記録します。値はFSU起動時から終了までの `duration_ms` とPHPピークメモリーの `memory_bytes` です。URL・要求本文は含めません。Webサーバーの全応答時間やプラグイン単体の追加処理時間を直接表すものではありません。

## 初回開発版での改善

通常の書込みは時間ファイル単位の期限切れ削除と容量整理を行い、部分的に期限を跨ぐファイルの全行再解析は行いません。行ごとの168時間期限による圧縮整理は、毎時の`fsu_prune_logs`ジョブで行います。時間ファイルの物理削除には最大約1時間の粒度があり、Cron停止・セーフモード・無アクセスではさらに遅れる場合があります。ZIP出力は行時刻で指定範囲を厳密に絞ります。

初回の `1.0.0-dev` で、通常要求が境界ファイル全体を繰り返し読み直す問題を修正しました。5.28MBの境界ファイルを含む200イベントの局所測定では、書込1件あたり約0.119msでした。これは過去の単一環境での測定で、`1.0.0-dev.1` の性能測定や実ホスティング全体の保証を意味しません。

ZIP容量予約では入力ログを消して空のZIPを作らないよう、事前に使用可能量を確認します。管理画面から変更できない内部テスト用の小容量設定では、512KiB未満の出力を拒否します。標準は500MiBです。取得時はヘッダー送信前にファイルを検証して開き、Content-Lengthと短い読み出しの検出を用います。読み出し・削除失敗のPHP警告で非公開パスや文字列がZIPへ混ざらないよう処理します。

## 1.0.0-dev.1 の再監査修正

期限切れZIPや時間ファイルが残った状態で、整理前の使用量を基にZIP出力を拒否する問題を修正しました。期限切れ整理と空き容量検査を同じ保管ロック内で順に実行し、保持中の入力ログをZIP予約のために消さない方針を維持します。

HTTPヘッダーが未送信でも、PHP出力バッファーには既に文字列が存在する場合があります。ZIP取得要求では、ヘッダー前に削除可能なバッファーと圧縮状態を確認・処理し、安全に処理できない状態では中止します。ダウンロード応答の終了処理で文字列が追加される場合も、ZIPへ混入させない対策を行います。通常ページの出力バッファーを一律に変更する機能ではありません。WordPressの通常の終了時バッファーフラッシュをZIP取得要求内だけで抑止し、ほかの終了コールバックは継続します。PHP出力バッファーを経由しないSAPIへの直接書き込み、ほかのコードによる意図的な出力制御の変更、プロセス強制終了まで完全に制御するものではありません。

いずれも信頼性と出力の整合性の修正で、未認証の遠隔悪用やCVEを確認したという主張ではありません。回帰試験の実行結果は検証記録を参照してください。
